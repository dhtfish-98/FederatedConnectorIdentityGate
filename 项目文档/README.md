# FederatedConnectorIdentityGate

Version **0.1.1** · Author **dhtfish98** · Status **public source; v0.1.0 publication independently verified; CVP eligibility OPEN**.

Version 0.1.1 corrects outdated publication wording and updates release-version metadata. The identity, session and resource controls are unchanged. The [publication record](VALIDATION.md#verified-v010-publication) binds the earlier release, main/tag CI and downloaded assets to their exact commit; current-version checks are reported with its release.

This Go library guards a downstream application's local account, session and resource binding after login through Dex. It verifies a Dex-signed ID token and binds the local subject to the trusted Dex issuer plus the signed `federated_claims.connector_id` and `federated_claims.user_id`. The email claim is display data. A deliberately email-keyed baseline exists only inside the live test, where two local identity sources use the same email and demonstrate the ownership collision.

The test starts two original loopback OIDC identity sources and a real Dex built from fixed commit [`c7ced47db7f9dc92192969e6c396e393275278eb`](https://github.com/dexidp/dex/commit/c7ced47db7f9dc92192969e6c396e393275278eb). It completes authorization-code exchanges, verifies Dex's signed tokens, and checks that the guarded application keeps the two identities, sessions and resources separate. Dex already preserves connector and user identity; this experiment addresses a separate downstream application's mapping. It does not claim or fix a Dex vulnerability.

To run the full validation from an extracted source archive, install Git and Go with toolchain auto-download support, then run `bash scripts/validate.sh` at the project root. The script fetches only the pinned Dex commit, keeps the Go toolchain, module cache, Dex build and test state under `Build/环境` or `Build/验证`, and writes a sanitized machine-readable result to `Build/验证/live-evidence.json`. It targets `./gate` explicitly so module downloads under a repository-local `Build` cannot be mistaken for project packages. It also compiles a separate consumer module under `Build/验证/consumer`. Network access is needed for the fixed source and Go dependencies. Set `FCIG_BUILD_ROOT` to a separate, trusted Build directory if the source checkout itself must remain source-only. A direct `go test ./gate` requires `FCIG_DEX_BIN` and `FCIG_BUILD_DIR`; the live test fails if the real fixed Dex binary is unavailable.

The calling application must put its persistent state in a directory it controls and protects. It must supply a trusted Dex issuer/client configuration and generate, retain and consume authorization state and nonce for each login; this library only verifies the supplied nonce against the signed ID token. This package does not sandbox the path, provide a multiprocess database, implement a full OAuth client, or replace production OAuth/OIDC operations. The test's HTTP endpoints bind only to loopback. See [design](DESIGN.md), [threat model](THREAT_MODEL.md), [validation](VALIDATION.md), and [third-party rights](THIRD_PARTY.md).
